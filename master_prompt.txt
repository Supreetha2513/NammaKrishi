MASTER PROMPT Farm Equipment Rental Marketplace – Owner Portal Web App Design and build a full‑stack web application for the Owner Portal of a Farm Equipment Rental Marketplace where equipment owners can list, manage, and monetize their agricultural machinery by renting it to farmers. The application should behave like an AI-powered e-commerce dashboard for farm machinery owners, enabling them to manage equipment listings, bookings, earnings, pricing strategies, and demand insights. The owner portal must integrate with a shared backend database used by both owners and customers. Do not hardcode or assume a specific frontend or backend framework; however, implement it as a modern full‑stack website with a clear separation between frontend (owner UI), backend APIs, and database. The backend can expose REST or GraphQL APIs. The frontend should be responsive and optimized for both desktop and mobile browsers. Core Purpose The Owner Portal allows machinery owners to: upload farm equipment for rent manage bookings and payments track revenue and performance receive demand insights automate listings with an AI agent enable dynamic pricing during peak farming seasons maintain equipment safety and verification status Shared Database Architecture The application must use a shared database used by both the Customer Dashboard and Owner Portal. Common tables used by both systems: Users Stores all platform users. Fields: id name phone role (customer / owner / admin) language_preference created_at Owners are users with role = owner. Equipment Stores equipment listed by owners. Fields: id owner_id name category description price_per_hour price_per_day location availability_status image_url created_at Owners manage equipment listings through the Owner Portal. Bookings Stores booking details. Fields: id equipment_id customer_id owner_id start_date end_date total_price booking_status payment_status created_at Payments Stores payment transactions. Fields: id booking_id payment_gateway razorpay_order_id razorpay_payment_id payment_status created_at EquipmentRequests Stores requests when equipment is unavailable. Fields: id customer_id equipment_name location request_status created_at Used for demand analytics. SMSNotifications Stores notification logs. Fields: id request_id phone_number message status created_at Used to notify farmers when equipment becomes available. Owner-Specific Tables EquipmentVerification Stores equipment verification information. Fields: id equipment_id owner_id verification_status document_url inspection_date verified_by created_at Used to show Verified Equipment Badge. EquipmentMaintenance Stores maintenance logs. Fields: id equipment_id owner_id service_type service_notes service_date next_service_due created_at DynamicPricing Stores pricing multipliers for high-demand seasons. Fields: id equipment_id season location demand_score price_multiplier start_date end_date created_at DemandAnalytics Stores aggregated demand insights. Fields: id equipment_category location request_count demand_score season updated_at OwnerEarnings Stores owner financial summaries. Fields: id owner_id total_earnings monthly_earnings completed_bookings last_updated AIListingSessions Stores interactions between owners and the AI listing assistant. Fields: id owner_id input_prompt generated_equipment_name generated_category generated_description suggested_price uploaded_images listing_status created_at EquipmentAvailability Stores availability calendar data. Fields: id equipment_id date availability_status booking_id OwnerNotifications Stores owner-specific alerts. Fields: id owner_id notification_type title message status created_at Owner Portal Web App Features 1. AI Agent for Automated Equipment Upload The web app must include an AI assistant that helps owners upload equipment listings automatically. Workflow: Owner types (and optionally records voice messages if supported in the browser): "Upload my tractor for rent in Mandya for ₹600 per hour." The AI assistant should: ask for missing information accept equipment photos (file upload) generate equipment description categorize equipment suggest pricing auto-fill listing fields allow confirmation before publishing The website should call AI APIs through a backend abstraction layer so the specific AI provider can be configured without changing business logic. 2. Equipment Listing Management Owners should be able to: add equipment edit listings upload multiple photos set hourly and daily rental prices toggle equipment availability delete equipment listings Each equipment card (or row in a table) should display: equipment image rental price location availability status verification badge 3. Verified Equipment Badge Equipment that passes safety verification should display a Verified Equipment badge. Verification may include: identity verification equipment registration maintenance inspection Verification status: pending verified rejected 4. Booking Management Owners must be able to view and manage bookings. Displayed information: equipment booked customer information booking duration total rental price booking status payment status Owners can: accept booking requests reject booking requests mark rentals as completed Booking statuses: pending accepted rejected completed cancelled 5. Earnings Dashboard The dashboard should display financial metrics including: total earnings monthly revenue completed bookings most rented equipment Charts should display: revenue trends booking activity Charts can be implemented with any modern web charting library. 6. Dynamic Pricing The system should support dynamic pricing during high-demand farming seasons. Pricing adjustments should depend on: season location demand number of booking requests equipment scarcity Owners should be able to: enable dynamic pricing override system suggestions Example: Normal price: ₹500/hour Peak harvest season: ₹700/hour 7. Demand Insights The web app should display equipment demand insights using farmer search data. Owners should see: most requested equipment demand location number of requests Example insight: "Harvesters are highly requested in Mandya district." 8. SMS Notification Automation If farmers requested unavailable equipment and an owner lists that equipment later: The system should automatically send SMS alerts. Example: "Good news! A tractor you requested is now available in your area." 9. Availability Calendar Each equipment listing should include a calendar. Owners can: mark unavailable dates see confirmed bookings avoid double bookings The calendar should be implemented with a web calendar widget and integrated with EquipmentAvailability and Bookings data. 10. Maintenance Tracker Owners should be able to track equipment maintenance. The web app should allow logging: service dates repair notes next maintenance date Maintenance reminders should be sent automatically and surfaced via notifications. 11. Owner Performance Metrics The system should track owner reliability. Metrics include: booking completion rate response time cancellation rate customer ratings Owners may receive Trusted Owner badges. 12. Smart Notifications Owners should receive alerts for: new booking requests payments received equipment demand trends maintenance reminders dynamic pricing updates Notifications should appear as: in‑app notifications (notification center UI) optionally browser push notifications (where supported) Web App Structure The web application should include the following pages/sections (SPA or MPA is acceptable as long as UX is smooth): Owner Dashboard Displays: revenue summary active bookings equipment count demand insights My Equipment Allows owners to: add equipment edit listings manage availability open availability calendar Booking Requests Shows incoming booking requests. Owners can accept or reject bookings. Earnings Displays revenue analytics and booking statistics. Demand Insights Shows equipment demand trends. AI Listing Assistant Chat-based interface for automated equipment listing. Maintenance Tracker Allows owners to log and manage equipment servicing. Notifications Displays system alerts and updates. Profile / Settings Allows owners to manage profile, language, and preferences. UI Requirements The Owner Portal website should include: clean modern UI intuitive navigation (e.g., top nav + side nav, or sidebar + header) responsive layouts for desktop, tablet, and mobile equipment cards or tables with images charts for analytics calendar widgets for booking availability Navigation Recommended main navigation items (sidebar or top navigation): Dashboard My Equipment Bookings Earnings Insights Notifications Profile Support deep linking to important views (e.g., specific equipment, booking details). Key Functional Requirements The full‑stack website must support: real-time or near real-time booking updates automated equipment listing via AI agent dynamic pricing adjustments equipment verification badges demand analytics maintenance tracking SMS alert automation revenue tracking
